## Controller execution contract 1.0

Only an explicitly configured development API process accepts `development_execution`; ordinary UI messages continue MOCK. This request must use a TEMPORARY conversation without Topic, a volatile store and one of the existing synthetic identities. It cannot contain authored context labels, revision commands, simulation flags or external source/path references. Persisted conversations are refused before registering input. This is an isolated development harness, not production authentication or a semantic private-data detector. Callers must supply original synthetic/non-confirmation inputs; metadata attestation does not prove that arbitrary text is safe.

`development_execution` has exactly: schema_version=`1.0`, capability_id, query (original ordinary question), input_class=`SYNTHETIC_NON_CONFIRMATION`, fixture_family, purpose=`DEVELOPMENT_INTEGRATION_ONLY`, timeout_ms. The Controller supplies request_id and source_id/version/SHA256/text from its accepted ledger event; original text is unchanged. Native research object identities remain inside the worker. Only normalized product expression objects, exact source anchors and a native derivation receipt digest cross back.

The JSON process request/response use version `1.0`, strict unknown/duplicate-field and nonfinite-value refusal, 64,000 UTF-8 source bytes / 16 sources, 8,000 question characters, 128 KiB envelope and 256 KiB response bounds. Each attempt is one process, no retries. Wall timeout is 1–10,000 ms (default 3,000). CPU is limited to 10 seconds; Linux additionally applies a 256 MiB address-space limit. macOS does not support that address-space limit, so wall/CPU/input/output bounds are enforced there. Worker environment omits inherited credentials, uses isolated Python without bytecode writes, denies network/child creation and file writes, and revalidates the exact artifact before invocation. Cancellation/timeout kills the process group and reaps it. No stderr or hidden reasoning is stored.

Real HCL callables perform provider-free source candidate preparation and modal expression checking. `EXECUTED` means an eligible source-anchored modal output exists. `NO_TREATMENT` means the selected available callable ran without eligible output. `UNSUPPORTED` means no bridge exists for that stable capability. Explicit ambiguity remains `UNRESOLVED`; runtime capacity/input failures are `FAILED`. Transport timeout/error without a trustworthy response records `executed=null`, operation UNRESOLVED and run UNKNOWN, never a manufactured false/true completion. CANCELLED remains terminal; explicit failed/cancelled retries create new attempt and operation IDs. Unknown transport is never blindly retried.

Controller receipts preserve REAL plus development_only=true, EXPERIMENTAL policy, production_enabled=false, source/config/runtime/bridge code digests, fixed interface/manifest identity, versioned operation flags and exact output refs. Selected, executed, result_produced, used_in_answer and actual_treatment remain separate. Direct arithmetic runs no specialized mechanism. The synthetic answer renderer quotes at most four checked public expressions; it does not create a model-generated answer, infer private belief, or insert HCL output into remembered context. Explain and read-only Lab bind the same recorded run; deletion removes nested request/output/receipt and stream copies. Concurrent revision withholds stale publication while preserving known execution flags. Temporary bodies and receipts disappear on restart; review exports must obey current deletion policy.
