# Assistant-first UX — Canonical A2

版本：2026-10-01。归属：[Product Master Plan 1.2](../HCL_ASSISTANT_PRODUCT_MASTER_PLAN.md)。本文件正式采用已确认 Review 的交互方案，替代 UX v1 中冲突的默认入口与展示要求；不是新增定位方案。下述为设计要求，非已实现声明。视觉见 [Visual System](VISUAL_SYSTEM.md)，待开发验收见 [Acceptance Matrix](ACCEPTANCE_MATRIX.md)。

## 1. 全局信息架构

主产品只有一个工作中心：聊天。Home 和 Conversation 是同一界面的空状态与使用状态。侧栏为新对话、搜索、最近对话；项目仅在需要或已经存在时出现；底部是记忆和设置。项目是前台唯一可选的跨对话容器，内部可以继续用 topic_id；不引入并行 Topic/Workspace/Case。

回答级递进路径：回答 → 查看依据 → 具体依据或变化 → 详细检查。Research Lab 从高级设置或详细检查进入。Explain、理解变化和 Inspector 是上下文视图，不增加三个一级导航入口。没有常驻右侧图谱、每轮 Lab 主按钮、前台 Base/HCL 或 HCL intensity 开关。

导航服务于找回工作，不服务于运行配置。当前对话范围可检查，但不是新对话必选表单。新对话不等于清空全局记忆；改变“下次新建”的默认值不悄悄改变当前会话范围。

## 2. 核心流程

### 首次打开与新对话

首次打开直接输入，提示“有什么需要帮忙的？”；输入框“输入问题或想法”。不用能力地图、Case wizard、人物表单或关系/责任研究分类。可用低权重提示说明能补资料和更正信息。第一次需要跨对话复用时再解释范围。

点击新对话立即聚焦输入。普通新对话默认本会话背景；用户需要时选择加入项目或临时对话。当前 prototype 保留一个清晰持续可见的“交互演示，不连接模型”环境标识，详情可展开；不能为视觉清爽隐藏 mock 身份，也不在每条回答重复开发免责声明。

### 普通聊天与后台变化

先回答用户问题；问题本身不是用户事实，不自动形成心理画像。无需专门处理时可以正常直接回答，不播报模块未启动。上传、注册、解析、选中和完整理解分别对待，文件内容不是控制指令。

| 变化类型 | 呈现 |
|---|---|
| 索引整理、无实质影响 | 不提示 |
| 明确背景更新且影响任务 | 回答中自然确认，例如按新的截止时间调整 |
| 旧建议/解释需要改变 | 说明改变，提供“查看变化” |
| 更正目标含糊 | 简短澄清，不改最近一条代替正确目标 |
| 相关更新未完成/失败 | 说明哪部分不能继续依赖，不假装已更新 |
| 专门处理无额外信息 | 通常不打扰，检查记录保留真实结果 |

不使用“新增认知节点”toast，不把版本递增当理解提升。状态变化与回答任务分开；更正+普通问题仍先处理更正。依赖失效但未重新评估的项目不能显示“不变”。

### 判断为什么改变

用户可自然询问“你之前不是这样说的，为什么变了？”回答围绕之前依据、新增或更正信息、受影响判断三部分组织。某个解释减弱不等于替代动机已被证明；系统现在修订对过去的重建，不等于人物过去自动获知今天的信息。

旧回答保留当时输入与依据；新分析为新 run。纠正旧错误、现在情况变化、降回猜测、假设另一种情况必须分开。假设不写回真实背景。

### 从普通聊天逐步检查

第一次展开只看有用依据、关键条件与缺口，不看 JSON 或能力目录。点击来源在同一侧栏内定位原文并能返回；不叠加多个互相遮挡的 modal，不丢失阅读位置和触发焦点。只有继续详细检查才展示局部依赖与执行记录。

### 多会话与长期背景

同一对话自然延续；项目内跨对话明确加入；跨项目不自动串联。同名人物不自动合并。当前使用背景能查看。修订影响相关理解，不自动重写所有历史答案；查看旧回答或继续相关任务时提示已不适用的依据。

## 3. 九个视图

### 3.1 Home / Chat

用户目标：不做配置即可开始获得帮助。

布局：左侧导航，中央简短空状态和 composer；已有用户可有少量“继续最近对话”文字入口，不做卡片仪表盘。主操作是输入、发送、附加资料。

默认隐藏：项目配置、认知状态、模型高级参数与 Lab。用户主动组织长期事项时才显示项目。

空状态：没有历史是正常的，不显示“尚未创建认知状态”。错误/不支持：服务不可用保留草稿；演示环境不能暗示开放问题会获得真实模型回答，不用无限 spinner。

### 3.2 Conversation

用户目标：围绕当前问题持续工作。

布局：轻量标题栏、单列消息、底部 composer。支持可读 Markdown、代码/引用/表格、复制、编辑自己的消息、停止、明确失败重试、附件讨论。正文优先，操作低权重但键盘/触屏可发现。

默认隐藏：run ID、route、state version、能力枚举。来源只在实际引用时出现；有可展示依据时出现“查看依据”，普通问答不强行填解释模板。

空状态沿用 Home。中断保留已生成内容并标未完成。失败重试为新 attempt；状态未知先恢复记录，不重复输入或修订。无专门 HCL 处理不是故障；在权限、来源与服务能力成立时继续普通回答。未获准模型路径不能用假回答冒充 fallback。

### 3.3 State Change / Insight

用户目标：知道什么变了，以及为何影响当前帮助。

布局：依附相关回答的一条变化摘要，不做独立 insight feed。展开显示旧依据、新信息、影响，主操作为查看依据、继续讨论、纠正理解。

默认隐藏：技术 diff、全部重算列表。仅影响回答/建议/计划或用户明确关心的背景时展开。无实质变化则不显示。

目标含糊先询问；不能仅递增版本号就显示更新成功。不支持局部修订时标该判断尚未重新评估。无额外价值不生成假洞见。

### 3.4 Explain — 前台“查看依据”

用户目标：判断回答是否值得依赖。

布局：约400px侧栏；优先当前问题相关依据，再关键条件、缺口与可定位来源。不强制填满固定六块。

主操作：查看原文、纠正相关背景、继续详细检查。默认隐藏对象ID、完整执行树；用户主动查看时再展开归属/时间/修订信息。

空状态：无记录就说没有可展示的背景依据，不事后补写理由。已删除/无权限则说明不可用，不能从缓存恢复。旧回答展示当时依据并服从当前权限。

Explain 是记录投影，默认零新模型调用；不是模型隐藏思维，也不证明内部机制对答案的因果贡献。重新分析必须显式新运行。

### 3.5 Advanced Inspector

用户目标：检查理解、来源或执行哪里可能有问题。

布局：可扩展详细检查视图，默认可读列表；信息与解释、变化、运行记录分组。点选判断后才展开局部支持/反证/依赖。

主操作：定位原文、查看历史、精准纠正、按权限导出。完整图谱与JSON仅技术详情；不默认全账户知识网络。结构化编辑是自然更正的补充，不要求用户填写心理真相。

空状态显示原始输入与覆盖情况，不编造结构。未选择、已选择未执行、执行无输出、有输出未用于回答、失败/未知分别呈现。连线与绿色节点不表达认知真理。

### 3.6 History / Memory

用户目标：找回过去，并控制未来会使用什么。

布局：历史/搜索面向原始对话；记忆面向可复用背景，两者可互相定位但不混成一张记录表。搜索给片段和位置；记忆给内容、范围、来源和最近变化。

主操作：搜索/打开、更正、不再使用、删除。生命周期枚举、hash、support groups隐藏；次级动作进入菜单，不铺满按钮。

空状态“尚未保存可跨对话使用的背景”不等于没有历史。停止使用必须影响未来检索/回答；删除清理相应副本与派生物，独立来源仍有相同信息时说明范围。错误不先显示成功。未解析不等于事情不存在。

### 3.7 Compare

用户目标：研究某处理是否改变结果、是否值得保留。

布局：Research Lab 内共享问题与双列答案；先看模型、来源、允许上下文、工具、预算与实际处理差异，再看输出。支持盲式查看后揭示身份。

主操作：核对条件、查看差异、记录审阅、导出。普通聊天不显示开关或灰色占位；原始prompt/token/config在研究详情展开。不得默认高亮HCL为更好。

空状态：没有合格运行不伪造对比。无处理差异说明不能检验专门增益；一侧失败不直接判另一侧胜利。条件不同只能描述，不能冒充公平实验。当前未获准执行，只有设计规格与门槛说明。

### 3.8 Settings

用户目标：理解并控制行为。

布局：一般、个性化、记忆与数据、模型与连接、高级。优先语言、显示、输入、范围、导出与删除。

主操作：管理明确偏好与真实可执行的设置。首发一个推荐模型；未接入或未授权的服务不列为可用能力。无 HCL intensity 滑块。

未配置真实服务直说未连接。保存失败不假成功。临时对话、浏览器/服务器存储、备份与供应商保留分别说明。历史调试参数与研究配置默认隐藏。

### 3.9 Research Lab

用户目标：验证、调试、审计，而非日常聊天。

布局：独立工作区与“返回聊天”，围绕运行、来源和实验组织。可读检查为默认，深层技术信息可高密度展开。主操作为获准的检查、回放、比较、导出。

不自动导入私人对话；送入研究用途需要明确数据/用途确认，不回写真实记忆。空状态使用获准原创synthetic材料；能力缺失、范围不支持、授权未满足解释原因。

失败、无处理、无增益和不确定都是合法结果，不要求每次产出 insight。当前 Lab 仍只读/受限，不因这份设计开放 provider 或生产能力。

## 4. 前台术语与技术术语

| 内部 | 普通表达 |
|---|---|
| context state | 当前使用的背景 |
| revision | 更新了哪些信息 |
| source version | 当时的原文 |
| dependency | 这个判断依据什么 |
| snapshot | 当时的记录 |
| unsupported | 这部分暂时无法处理 |
| no treatment | 通常不显示；详细检查说明未产生专门处理结果 |
| epistemic status | 据你描述 / 对方的说法 / 一种可能解释 / 信息不足 |

技术词进入技术环境才显示。Understand → Revise → Judge → Help → Act 不变成五个导航页；Judge 不显示为当前能力或进度阶段。

## 5. 输入、恢复和无障碍要求

Composer 与消息列对齐，自适应高度；Enter发送、Shift+Enter换行必须正确处理中文组合输入。文件选择后展示附件与读取状态；错误保留草稿。停止和发送位置稳定。

只有用户本来在底部时跟随流式滚动；向上阅读时不拉回底部。焦点、Escape、键盘导航、缩放、触屏目标和减少动态效果需要真实验收。窄窗口折叠导航或切换详细检查布局，不把三栏硬挤在一起；移动端用全屏 Explain/Inspector。

## 6. 当前界面迁移

删除主体验中的状态版本、路由、重复MOCK、每轮Lab按钮、常驻Advanced、Topic必选和已保存重复标签。重置预览进演示菜单；记忆管理从标题前移到记忆入口。环境标识仍需真实可见。

先完成 [P0-01](PRODUCT_REFINEMENT_WORK_PACKAGES.md#p0-01--truthful-preview-contract-repair) 的行为兑现，再做主界面重构。不能用隐藏按钮替代已承诺行为修复，也不能只做配色美化。原生支持确实缺失时可以删除误导动作，但必须保留明确能力边界。

## 7. Continuum V1 实施补充（不改变上述产品语义）

本节按[正式采用门槛](design/continuum-v1/README.md)生效；草稿不覆盖 main。已完成的 P0/P1-01 与现有 P1-02 writer/PR 保留，不从第6节历史迁移顺序重开旧包。

首页、对话和依据/修订分别对应 UI-01、UI-02、UI-03。保留本轮图稿的布局、光感、材质和配色；页面组件、长内容、文件、响应式、键盘、加载/异常及 motion 以 [Implementation Spec](design/continuum-v1/IMPLEMENTATION_SPEC.md) 为本文件的实施细则。它补齐静态图未表达的状态，而非重新定义产品。图中平台导航、未支持工具、文案和引用按设计目录的语义例外处理，不能扩权。

同一工作面和输入对象贯穿 Home/Conversation。依据从当前回答展开，来源在同一详情层深入，返回恢复原段落/触发点及焦点。记录稳定的会话/回答/段落身份和视口相对位置，而非仅保存 scrollTop。正常关闭尊重用户在主文中的主动滚动；“返回回答位置”才显式恢复最初触发点。窄屏使用相同的可返回详情栈，不创建另一套对话产品。

修订提交、受影响分析的重评、回答生成是独立状态。已提交未重评显示“这条背景已更正；相关旧回答尚未重新分析”；提交成功但回答失败不回滚更正；未知先恢复记录。原答案保持当时记录，重分析为新 run。变化界面不把版本号、动画结束、绿色节点或来源数量当作理解/正确性。

两套数字形象共用插槽且可关闭，候选未定不阻塞共享界面。动作只能响应真实交互/状态，不暗示未获准的聆听、后台分析或 Judge。真实三轮长内容、来源返回、修订状态及视觉还原验收见 [V01–V10](design/continuum-v1/ACCEPTANCE.md)；静态图片不是可用性或运行证据。
